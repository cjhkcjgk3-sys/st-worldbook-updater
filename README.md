# 世界书更新器 v1.4.0

在酒馆里并排浏览两本世界书，批量更新或融合到左侧原书。两侧条目列表固定左右并列，点选任一条目后正文会自动在下方展开，方便对照。支持电脑和手机，无需模型 API、酒馆助手或额外服务器。

## 安装与升级

面向 SillyTavern 1.18.0 及更新版本；接口已核对 1.18.0、1.19.0 官方源码，用户实际安装环境仍需试用验证。

### 通过酒馆直接安装

在酒馆“扩展 → 安装扩展”中粘贴下方仓库链接，完成后刷新网页：

```text
https://github.com/cjhkcjgk3-sys/st-worldbook-updater.git
```

后续可以在酒馆的扩展管理中检查更新。

### 手动安装或覆盖

1. 解压安装包，找到 `st-worldbook-updater` 文件夹。
2. 将整个文件夹放进运行酒馆的设备上的 `SillyTavern/data/default-user/extensions/`。多用户环境把 `default-user` 换成对应账号目录。
3. 确认文件位于 `SillyTavern/data/default-user/extensions/st-worldbook-updater/manifest.json`，避免多套一层目录。
4. 刷新酒馆网页，在扩展设置中点击“打开世界书更新器”。

已安装旧版本时，覆盖同名扩展文件夹后刷新即可；扩展 ID 保持不变。

手机浏览器访问电脑或服务器上的酒馆时，扩展也安装在电脑或服务器。酒馆的“安装扩展”输入框用于 Git 仓库链接；本 ZIP 使用解压安装方式。

## 核心操作

左侧选原世界书；右侧选已有世界书，或直接打开酒馆原生世界书 JSON 文件。

在原有下拉框选择操作，共用一个执行按钮：

| 选项 | 已配对且勾选的条目 | 右侧勾选的新条目 |
| --- | --- | --- |
| 更新 · 仅正文 | 仅替换正文 | 不追加 |
| 更新 · 完整条目 | 同步新版明确提供的标题、关键词和运行设置 | 不追加 |
| 融合 · 仅正文 | 仅替换正文 | 追加完整新条目 |
| 融合 · 完整条目 | 同步新版明确提供的标题、关键词和运行设置 | 追加完整新条目 |

默认是“更新 · 仅正文”。完整更新保留目标编号、列表位置和来源未提供的扩展字段；插入顺序等运行设置仍按新版更新。新增条目分配新的本地编号，排到列表末尾，保留完整设置。

左侧独有及未勾选的条目保留，原书名称、绑定和顶层元数据保留。相同条目跳过；插件不自动删除条目。写入用于后续生成请求，已有聊天消息保持原样。

## 定点名单

按角色名只处理指定的人物，适合把一本“全家桶”世界书分发回各个作品的书里：名单外的人物既不替换，也不复制。

底部「定点名单」每行一个名字；留空则整本参与，行为与之前一致。

| 写法 | 效果 |
| --- | --- |
| `爱芮` | 与条目名精确匹配 |
| `维琳娜·艾嘉德` | 忽略全／半角、标点、空格与间隔号 |
| `零号·安比（安比·德玛拉）` | 括号里的英文名、曾用名也参与匹配 |
| `雷电将军=雷神` | 一行写多个叫法，任一命中即可 |
| `拉菲` | 自动带上 `拉菲（改造）` 这类形态条目 |
| `作品别名：原神=Genshin` | 名单里带作品名时先去掉再比较 |

匹配只比名字，不做包含或模糊匹配：`安比` 不会命中 `零号·安比`，`小安比` 不会命中 `安比`。名字对不上时，面板会列出「名单未找到」的条目，不会静默写错。

开启「匹配置顶（仅显示）」后，两侧列表里命中的条目会排到最前，块内顺序跟随母本：母本第 1、3、6、7 位的四个角色，置顶后在列表里就是第 1、2、3、4 位，其余条目保持原相对顺序。

这是**显示层的排序**：不写回世界书、不改 `displayIndex`、不动正文和注入顺序。清空定点名单或断开匹配，列表立刻恢复原顺序。

「复制来源条目名」把右侧来源书的条目名按行复制出来（自动去掉分类前缀与楼层元数据），可直接交给 AI 挑出属于某部作品的角色，再粘回名单，保证与书里逐字一致。

名单命中的条目里，左侧已有的走“更新”，左侧没有的走“融合”新增；两者可以在同一次执行里完成。

## 条目设置（批量）

母本里的条目设置可以批量改好，再同步到目标书，不用再去那本书逐条改。面板折叠在底部，默认收起。

支持的核心设置：

| 设置 | 说明 |
| --- | --- |
| 注入位置 | 角色前 / 角色后 / 作者注上 / 作者注下 / 指定深度 / 示例上 / 示例下 |
| 深度、插入角色 | 仅在“指定深度”时生效 |
| 注入顺序 | 数字越小越先注入 |
| 常驻（蓝灯） | 开=每轮都注入，关=关键词触发 |
| 不可递归、防止进一步递归、延迟到递归、无视回复限额 | 四个递归开关 |

填写方式：字段选「设为」或「调整」（数字字段可以写 +2、-3），没选的字段不会提交。「作用范围」可选定点名单命中、母本全部条目、列表里勾选的。

两个按钮都要确认后才写入：**应用到母本**、**同步设置到目标书**（按配对关系把母本的设置覆盖到目标书）。标题、关键词、正文一律不动。

## 勾选与配对

常用批量操作集中在菜单中，避免增加一排按钮。

| 入口 | 可用操作 |
| --- | --- |
| 勾选操作 | 全部勾选、全部取消；融合模式另有“仅勾选更新”“仅勾选新增” |
| 配对操作 | 配对所选、解除所选配对、解除全部配对、重新自动匹配 |
| 配对操作中的新增标记 | 融合时可将待处理条目标记为新增，或取消新增标记 |
| 正文对照 | 点选条目后，下方自动并排显示两侧正文和关键词；中间分隔条可拖动调整列表与正文的高度 |

批量勾选对整组世界书生效，包括搜索隐藏的可执行项；搜索时会明确提示这一范围。全部取消可以直接清空部分勾选，不需要先全选。已配对条目的左右复选框同步。

勾选与点击条目是两件事：勾选决定写入哪些内容，点击决定当前查看或手动配对的对象。

插件结合标题和完整主关键词自动配对。唯一、无冲突且有变化的配对默认勾选。“新条目”在融合模式下可勾选追加；重名、共享或部分重叠关键词等歧义项显示“待处理”，不会被批量全选自动追加。确认确实属于独立新条目时，选中右侧条目，在配对操作中标记为新增。完全重复的条目跳过。

切换更新/融合或正文/完整范围会保留已有勾选意图。重新载入、重新自动匹配或切换两边世界书会重建配对与默认勾选。执行前确认窗口会列出目标书、更新数量和新增数量；取消确认不会写入。

## 界面与手机操作

窗口沿用酒馆主题色、弹窗、按钮和输入框样式。电脑与手机都保留原书在左、新版在右的双栏列表；不会在手机上切成单侧标签。点任一条目后，窗口下方自动展开原书/新版正文并排区，不用再找「查看正文」按钮。选中已配对条目时，另一侧会同步定位到对应条目。

窗口右下角有浏览器自带的缩放柄，上下拖动可以调整窗口高度，内容多时拉高、内容少时压低，和酒馆输入框上的那个是同一个控件。列表与正文之间还有一条可触摸拖动的分隔线。往下拖会给列表更多空间，往上拖会给正文更多空间；键盘可用上下方向键微调，也可用 Home/End 调到边界。顶栏右上角的展开图标可放大或还原整个窗口。点开右上角更多菜单可重新载入或关闭窗口。

手机屏幕较窄时，左右两列仍同时显示；可以缩放整个窗口，也可以拖动分隔线决定显示几行条目或多看正文。定点名单、配对与条目操作折叠收纳，短屏时可从顶栏更多菜单展开；更新方式、已选数量和主操作保持在底部。短横屏与搜索键盘弹出时会压缩次要控件，为列表留出空间。

手动配对时，先后点选左右条目，下方正文会同时显示两侧内容；再展开「配对与条目操作」选择「配对所选」。勾选框仍只决定是否写入，点击条目只负责选中和查看。

## 支持范围

- 一次处理一组世界书，融合后的总条目数最多 10000；本地 JSON 文件上限 20 MB。
- 接受酒馆原生世界书 JSON：`entries` 为对象，条目正文为字符串；不接收角色卡、条目数组或压缩包。
- 正则关键词按文本比较，正文按纯文本显示；预览不执行 HTML、脚本、宏或模板。
- 删除、直接编辑及条目拆分合并继续使用酒馆原生编辑器。
- 浏览器需支持原生对话框；写不进去会报错，不会静默成功。
- `examples` 提供演示旧版和新版，可用于试用更新、融合与恢复。

## 源码与验证

运行代码无额外依赖。扩展入口是 `index.js`；`core.js` 负责配对、定点名单匹配、替换与融合，`host.js` 负责酒馆读写核验，`ui.js` 与 `style.css` 负责界面。

数据与异常测试：

```sh
npm test
```

当前 66 项：配对、替换、融合回归，加定点名单、显示排序、条目设置与无备份保存用例。

浏览器测试另需开发环境安装 Playwright 与 Chromium：

```sh
node tests/browser-smoke.mjs
```

浏览器测试使用本地模拟酒馆接口。检查记录见 `VERIFICATION.md`，续接状态见 `NEXT.md`，当前范围见 `PLAN.txt`。
