世界书更新器｜项目规划 v1.1

一、目标与范围

一个可在电脑和手机上使用的 SillyTavern 浏览器扩展，以双窗口完成世界书条目对照、自动配对、批量更新和融合。
一次处理一组新旧世界书；尽量复用酒馆本身的读写、保存与刷新能力。

v1.1 在用户确认的首版基础上加入条目融合，并审查批量操作的完整性；不扩展多本同时处理、自动删除、AI 匹配或复杂历史管理。

二、操作闭环

选择左侧原书 → 选择右侧来源或读取原生 JSON → 自动配对和识别新条目 → 查看与手动纠正 → 勾选 → 选择更新/融合及正文/完整范围 → 确认更新和新增数量 → 备份、保存、服务器回读核验。

原世界书是正式数据源；来源文件、配对和勾选是本次临时状态；备份存于独立的浏览器持久存储。

三、界面与批量操作

只使用一个主窗口，列表左右各半。每侧有选书、标题/关键词搜索和条目列表；列表显示标题、状态与勾选，已配对条目的左右勾选同步。

正文查看沿用同一入口，支持双侧对照及单侧阅读。手机竖屏上下各半，横屏和电脑左右各半；返回保留列表位置，按钮触摸区域约 44 CSS 像素。适配小屏、横竖屏与搜索键盘可视区域变化。

现有操作范围下拉框提供四种组合：更新正文、完整更新、融合正文、完整融合。共用一个执行按钮，不新增独立融合按钮。

勾选操作集中为一个菜单：全部勾选、全部取消；融合模式可仅勾选更新或仅勾选新增。全选作用于整组数据，包含搜索隐藏项；搜索时明确提示范围。部分勾选可以直接全部取消。

配对相关操作集中为一个菜单：配对所选、解除所选、解除全部、重新自动匹配。融合模式对待处理项提供标记新增及取消标记。查看正文保留直接入口。备份下载和恢复继续放在已有折叠区域。

不增加拖动分隔线、布局偏好、联动滚动、逐字差异高亮、拖拽或长按专属操作。

四、匹配与融合规则

综合标题和完整主关键词集合，仅在关系唯一且无冲突时自动配对。部分关键词重合不自动认定为同一条目。内部编号只在当前书内定位，不作为跨书身份。

原书独有内容保留。来源中明确独有的新条目可选追加；共享关键词、重名或无身份信息等歧义项留待处理。完全重复的来源副本或已有相同条目跳过，批量全选不会追加待处理项。

新条目分配不冲突的原生编号，追加到列表末尾，保留完整设置。已配对条目保留目标编号与列表位置。融合后再次载入相同来源，不重复追加。

正文范围只替换已有条目正文；完整范围同步来源明确提供的字段，并保留来源未提供的扩展字段。两种融合范围中的新增条目都携带完整配置。可选的 originalData 导出表示同步维护。

正则关键词只按文本比较；正文只按纯文本展示。预览不执行脚本、HTML、宏或模板。

五、选择状态与失败处理

点击选择与勾选执行互相独立。模式/范围切换保留勾选意图；更换数据、重新载入或重新匹配会重建配对和默认勾选。确认取消不写入或覆盖备份。

空原书可通过融合加入条目；空来源或没有可执行内容时禁用执行按钮；空列表和搜索无结果分别提示。

操作前重新核对目标。预览后原书有变化、被删除或改名时停止写入。备份必须持久成功后才写入；在内存中完成整组更新和新增后，尽量单次保存目标书。保存后从服务器回读核验，不能把缓存或 Promise 完成当作成功。

保存结果不明时保留备份并阻止盲目重试；重新打开后核验上次结果。恢复前确认目标；有后续修改时明确整书恢复的覆盖影响。

六、保留与边界

只修改勾选条目，保留原书名称、绑定、顶层元数据与未选内容。不重写已有聊天消息，不干预已发出的生成请求。

每本书保留最近一次操作前的完整备份，按账号隔离，提供原生 JSON 下载与整书恢复；不提供云端备份同步或多版本历史。

总条目上限 10000；本地文件上限 20 MB。只接受原生世界书 JSON，不接收 PNG、TXT、ZIP 或其他条目数组格式。

七、技术与交付

原生 JavaScript 模块、少量 CSS 和标准 manifest.json；不引入 React、酒馆助手、额外服务器或模型 API。

三个主要职责：数据配对与融合、酒馆读写及备份、双窗口交互。依赖版本按官方源码与运行时能力检测处理。

交付完整源码、可安装 ZIP、示例世界书、简明说明、自动检查及当前续接记录。扩展 ID、设置命名与备份格式保持兼容。

八、验证与续接

数据测试覆盖配对、共享关键词、批量勾选、融合编号冲突、重复导入、字段与导出表示保留、容量、备份与保存失败。
浏览器检查覆盖手机/电脑尺寸、批量菜单、筛选范围、模式切换、单侧查看、空书、取消确认、融合保存与恢复、失败和中断核验。

真实酒馆安装、宿主事件表现与真实手机触摸验收单独记录；当前事实以 NEXT.md 和 VERIFICATION.md 为准。完成本次范围后停止扩展，按具体反馈继续修改。
